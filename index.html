分成机制（核心优势）
定价权：完全归商家
收款权：完全归商家
结算方式：按调用量结算
流量成本：零流量成本
平台分成：暂未公开（早期红利期倾向开发者）
SkillPay关键能力
核心能力：
• 企业认证后绑定微信支付商户号，即可接入SkillPay
• 已有Skill通过简易改造（X402协议?）封装为Pay Skill
• 上架后自动具备向所有接入Agent收费的能力
• 用户在Agent对话中触发支付，在手机上确认完成
• 定价权和收款权完全归商家，按调用量结算

Skill改造对比（封装X402协议前后）：
改造前：收到请求 → 直接干活 → 返回结果
改造后：收到请求 → 判断需收费 → 调微信支付下单、X402预下单 → 返回payment_code给Agent发起支付 → 用户手机确认 → 支付成功 → 干活 → 返回结果
工作量约50行代码，无需自建支付页面和处理用户资金

企业接入流程：
企业认证 → 绑定微信支付账户 → 上传Skill并设置定价 → 简易改造封装为Pay Skill → 上架发布 → 用户付费调用 → 按调用量结算

用户调用流程：
① 用户在WorkBuddy/QClaw等Agent中通过SkillHub CLI安装Pay Skill
② 在对话中调用该Pay Skill（如"帮我生成一张图片"）
③ 首次使用需绑定微信：Agent弹出微信授权二维码 → 用户打开手机微信扫码 → 在微信中开通"AI专属卡"（独立于主账户的专用钱包），往卡里充值，完成授权绑定
④ 后续每次付费：Agent向用户手机发起支付确认请求 → 用户在手机上查看金额并确认（指纹/面容）→ 从AI专属卡扣款 → Skill继续执行并返回结果
⑤ 全程不跳出Agent对话，资金安全隔离

付费模式

Skill上架时可选择两种付费模式：

按次购买（消耗积分）

• 用户消耗账户积分，每次使用扣一次
• 仅限个人付费版用户可用
• 积分来源：订阅套餐赠送/充值购买/每日登录送

订阅（一次买断）

• 用户直接支付现金，按月/季/年订阅
• 订阅期内无限次使用，不扣积分
• 订阅成功后不支持退款
• 订阅到期后自动切回按次模式（继续用就扣积分）

积分体系

📦 订阅套餐送积分
• 个人进阶版：39.9元/月 → 3万积分
• 个人高阶版：99元/月 → 9.9万积分
• 个人旗舰版：199元/月 → 19.9万积分
• 个人尊享版：999元/月 → 99.9万积分
💳 充值购买积分
• 可购买档位：1万、5万、10万等
• 有效期1年
• 适用于高阶版及以上套餐用户
🎁 免费获取积分
• 每日登录：送1500积分（1天有效）
• 新用户注册：一次性送1500积分（30天有效）
• 邀请新用户：送6000积分（30天有效）

附-扣子开放上架付费技能的合规支撑分析

扣子平台允许个人开发者和企业开发者上架付费技能，背后是基于一套严谨的法律和合规框架来支撑的，核心是通过与支付渠道合作以及平台自身持牌两个层面来解决合规问题的：

🔑 通过与支付宝合作，解决个人开发者的收款合规

这是最关键的一环，它解决了个人开发者最头疼的资质和收款问题。

联手支付宝，降低门槛：扣子与支付宝合作推出了"支付宝商家入驻Skill"。这个工具专门简化了个人开发者开通合规收款渠道的流程，你甚至不用注册支付宝开放平台账号，只需上传几张应用截图，就能完成商家认证。

官方合规路径：这意味着，个人开发者通过这个通道获得的收款权限，背后是支付宝作为持牌支付机构完成的合规审核，为个人开发者提供了一条"合法合规地开启收款功能"的官方路径。

🏦 平台方（火山引擎/字节跳动）的合规保障

平台本身也持有开展相关业务所需的关键资质，这是整个交易能够合法进行的法律基础。

ICP经营许可证：根据工信部公示的信息，北京火山引擎科技有限公司（扣子平台关联方）持有编码为京B2-20202418的《增值电信业务经营许可证》。该许可证的业务种类明确包含"信息服务业务（仅限互联网信息服务）"和"在线数据处理与交易处理业务"。这涵盖了平台提供信息服务和促成在线交易的核心经营活动。

数据安全保障：在支付数据安全层面，火山引擎也获得了PCI DSS（支付卡行业数据安全标准）认证，这保证了其处理支付相关数据符合国际安全标准。

⚖️ 开发者与平台间的契约约束

除了外部资质，平台用户协议也明确了双方的权利和义务，构成内部的法律约束。

实名认证要求：扣子的《用户协议》明确要求用户注册时提供真实身份信息，并按规定完成实名认证。这是平台履行合规义务、进行有效管理的前提。

行为约束与平台权利：协议中，用户需承诺账号信息不违反法律法规，并对自己的行为承担全部法律责任。同时，如果平台认为用户违反规定，有权禁用其账号，这为平台管理付费技能的上架和运营提供了依据。

总结：扣子技能商店能允许个人和团队直接上架付费技能，靠的是 "合作持牌支付机构解决个体资质问题 + 平台自身获取关键业务牌照 + 用户协议作为法律契约" 这三重保障。这套机制让个人开发者的商业化有了合规的"通行证"，也让整个交易链条处于法律框架的监管之下。

付费Skill完整工作流程（扫码支付模式）

💡 完整流程如下：

Step 1：用户发起请求
用户在Agent对话中输入需求（如"帮我查一下最近的中标公告"）→ Agent调用对应的付费Skill API。

Step 2：Skill判断是否需要收费
Skill收到请求后，检查是否需要付费：
• 不需要付费 → 直接返回结果
• 需要付费 → 调用平台统一支付API（传参：金额、订单号、商品描述）

Step 3：平台生成付款二维码
平台支付API接收请求后，调用支付宝/微信支付接口，生成付款二维码链接，返回给Skill。

Step 4：Agent展示二维码
Skill将二维码返回给Agent → Agent在对话界面展示付款二维码。
这是Agent唯一需要做的事——展示一张图片。任何Agent都能做到。

Step 5：用户付费调用
用户掏出手机 → 打开支付宝/微信 → 扫一扫二维码 → 确认支付。
• 钱进入平台在支付宝/微信的商户账户
• 用户手机上会显示支付成功

Step 6：平台通知Skill继续执行
支付宝/微信通知平台"已收款" → 平台通知Skill"用户已付款" → Skill执行正式业务逻辑 → 返回结果给用户。

Step 7：月度结算到企业对公账户
平台每月汇总企业所有Skill的收款总额 → 扣除平台服务费 → 统一结算到企业绑定的对公银行账户。

核心节点规划说明

🔐 企业认证（复用华为云现有能力）

• 复用华为云企业认证：华为云账号实名认证已支持企业认证（营业执照、法人信息），企业客户可直接复用
• 入驻即开通：已企业认证的华为云账号，自动获得付费Skill入驻资格，无需额外申请
• 作用：确认企业身份真实可信，出了事可追溯

💳 绑定对公账户

• 绑定企业对公银行账户：企业提供对公银行账户信息，用于接收月度结算款项
• 作用：确认"钱打到哪"，企业认证（你是谁）+ 银行账户（钱到哪）= 完整的商业资质

📦 封装付费Skill（企业唯一需要改造的）

企业要做的事：在Skill中增加"先收费再干活"的判断逻辑 + 调平台支付API

改造前：收到请求 → 直接干活 → 返回结果
改造后：收到请求 → 判断是否需付费 → 需要则调平台支付API（传金额）→ 平台返回二维码 → 返回给Agent展示 → 收到付费通知 → 干活 → 返回结果

具体改造点：
• 定义计费规则（按次/按量/包月）
• 调用平台统一支付API（一行代码：传订单号+金额+商品描述）
• 将平台返回的二维码展示给用户
• 收到支付成功回调后，执行业务逻辑

不需要做的：
❌ 不需要对接支付宝/微信支付API
❌ 不需要注册支付商户号
❌ 不需要自建支付页面
❌ 不需要处理资金结算
❌ 不需要关心用户用支付宝还是微信

💰 设置定价与上架发布

• 计费模式选择：分阶段建设按次调用、次数包、包月等多种定价能力
